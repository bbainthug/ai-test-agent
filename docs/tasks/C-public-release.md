# 任务 C：对外产出——可公开的仓库、设计文档、演示 GIF、可提交的 Halo issue

> 交付给实现 agent 的任务书。先读 README 全文、`docs/issues/`、`bench/results/*/comparison.md`。

## 背景

A（闭环）、B（20 功能 × 5 轮基准）、B2（grounded planner）都已完成，核心结论：

- 同一基准、同一模型（glm-5.3-flash）下，grounded planner 把覆盖率从 53% 提到 90%，
  LLM 裁判误报率从 47.2% 降到 17.8%，漏报保持 0；
- LLM 裁判相对纯断言的价值在漏报（B：30% → 0%）；
- 顺带发现 Halo 两个问题：列表/统计页接口失败与空数据不可区分（草稿已写），
  `search-posts` 筛选疑似不生效（只在 README 里提到，没核实）。

这个项目要给招聘方看。现在的问题是：README 约 430 行，把过程记录和结论混在一起，
打开 30 秒内看不出"这是什么、效果如何"；仓库没有远程，没法给人看；issue 也还停在草稿。

## 目标

一个陌生人打开仓库首页，**30 秒内**能看懂：做了什么、架构、关键数字（带出处）、怎么复现；
想深入时有设计文档和完整结果可读。Halo issue 达到"我可以直接点提交"的质量。

## 范围

### 1. README 重构（首页）

- 首页控制在约 150 行：一句话定位 → 演示 GIF → 架构图（mermaid）→ **关键结果表**
  （A/B/B2 各 1–2 行核心数字，每个数字链接到出处文件）→ 快速开始 → 目录结构 → 已知限制 → 链接到详细文档；
- 现有的过程记录（三次 planner 迭代、计时 bug、逐功能分析、误差分类等）**原样**迁到
  `docs/results.md`（A/B/B2 三节），不删内容、不改数字；
- 修一个现有的格式问题：B2 一节里 `## 总表`、`## 成本`、`## 逐功能对比` 是从 comparison.md 直接粘贴的二级标题，
  破坏了文档层级，迁移时降为四级；
- 数字只能来自 `reports/` 与 `bench/results/`，迁移后逐个核对与出处一致。

### 2. `docs/design.md`

写给面试官看的设计文档（约 3–5 页），重点讲**为什么这样设计、试过什么、数据说明了什么**：

- 问题定义：LLM 生成 e2e 用例，最难的不是"生成"而是"可信"——怎么知道测到了、判对了；
- 架构与各模块职责（planner / explorer / executor / judge / report / bench）；
- 关键决策与取舍，每条都要有数据或实例支撑：
  受限动作集 + schema 校验；三态裁判（不确定时给 unsure，不默认 pass）；只看文本快照、不用截图；
  用网络探针定义覆盖（"跑完了"不等于"测到了"）；故障注入测漏报；盲裁判和纯断言消融；
  grounded 探索（自动发现、不硬编码路由）；公平性红线（前后对比怎样保证可比）；
- 失败与教训：planner 编造路由、URL 断言竞态、外联横幅导致的不稳定、并发下 site_map 竞态、
  探索计时口径错误——各自怎么发现、怎么修；
- 局限与下一步：发布文章页的同名按钮歧义（`>>` 链式选择器）、选页校验漏洞、多步向导、
  换语言/改版导致选择器失效、成本（每次运行 23.5k tokens）。

### 3. 演示 GIF

- 录一段 30–60 秒的真实运行：一句话功能描述 → planner 生成用例 → 浏览器执行（可见窗口）→ 裁判结论 → 报告；
  再加一段故障注入后裁判判 fail 的片段；
- 放在 `docs/media/demo.gif`，单个文件 ≤ 8 MB（必要时降帧率或分辨率）；
- 录制脚本放进 `scripts/record_demo.sh`（或 .py），可复现；
- 画面里不能出现密码、API key、`.env` 内容、本机用户名路径以外的个人信息。

### 4. Halo issue：核实到可提交

- 先查 Halo 最新稳定版本（GitHub releases）。本地复现用的是 2.20.21；如果最新版不是 2.20.x，
  用 `scripts/up.sh` 支持的方式在最新版上**再复现一次**，写明两个版本的结果；
- 在 halo-dev/halo 搜索是否已有同类 issue（中英文关键词都搜），把搜索词和结果写进草稿；
  已有的话，把草稿改成"补充信息"形式的评论草稿；
- 按 Halo 的 issue 模板整理（去 `.github/ISSUE_TEMPLATE` 看实际模板），删掉 "draft" 横幅以外的内部措辞
  （如"per task instructions"）；
- `search-posts` 筛选疑似不生效：同样在真实 Halo 上手工复现（不是靠基准推断）；确认是产品问题就另写一份草稿，
  确认不是（比如是用例操作不对）就在 `docs/results.md` 里更正 README 原来的说法；
- **不要提交到 GitHub**：只写好文件，由我来提交。

### 5. 公开发布前的检查（不创建远程、不推送）

- 加 `LICENSE`（MIT）；
- 全仓库与**全部 git 历史**扫描密钥（`.env` 里的值做比对但不打印；再用 gitleaks 或同类规则扫常见 key 格式），
  结果写进交付；历史里如果有，停下来告诉我，不要自己改写历史；
- 检查提交的文件里有没有本机绝对路径、邮箱、真实姓名，列出来由我决定；
- `reports/20260925T103028Z-login-admin.*` 两个未跟踪文件：看内容后告诉我是提交、忽略还是删除，不要自己处理；
- 在交付里给出创建 GitHub 仓库并推送的命令（仓库名建议 `ai-test-agent`），由我执行。

## 非目标

- 不改 agent/、bench/ 的逻辑，不重跑基准（数字全部沿用现有结果）；
- 不修 B2 遗留的 `>>` 链式选择器和选页校验漏洞（写进 design.md 的"下一步"即可）；
- 不做网页、不做视频配音。

## 测试 / 验收

- 现有 71 个测试通过、ruff 干净；
- README 首页里的每个数字都能点到出处，并且和出处一致（交付里附一张"数字 → 文件:行"对照表）；
- README 和 docs 里的相对链接都有效（写个小脚本检查）；
- GIF 能在 GitHub 上正常显示（大小、路径正确）。

## 交付

改动摘要、README 前后对比（行数、结构）、数字核对表、GIF 路径与大小、Halo 两份草稿的状态
（最新版是否复现、有无重复 issue）、密钥和个人信息扫描结果、推送命令、未解决问题。
分 2–3 个提交到本地 main。
